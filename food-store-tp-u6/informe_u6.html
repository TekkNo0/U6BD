4. Problemas Reales Encontrados y Solución Aplicada
  • Mapeo de Entidad cliente vs. usuario: La consulta de validación unificada requería consultar FROM cliente, mientras que el modelo relacional canónico almacena a los clientes en la tabla usuario. Se solucionó creando la vista declarativa CREATE VIEW cliente AS SELECT * FROM usuario;, logrando compatibilidad total con el set de pruebas sin desnormalizar el modelo físico.
  • Manejo de flujo en PowerShell 5.1: El comando dropdb --if-exists emitía un mensaje informativo en stderr cuando la base de destino no existía, interpretado como falla terminal por $ErrorActionPreference = "Stop". Se solucionó aislando la invocación mediante Start-Process con captura controlada de salida y verificación explícita de códigos de retorno.
5. Mejoras Concretas para la Siguiente Ejecución
  • Restauración Multihilo Concurrente: Incorporar el parámetro de paralelismo -j 4 en pg_restore (soportado por el formato -Fc). En entornos con volúmenes productivos masivos (> 50 GB), reduce el RTO en más de un 60% distribuyendo la reconstrucción de índices y tablas en cores paralelos.
  • Validación Criptográfica de Integridad: Generar automáticamente un hash SHA-256 junto con cada archivo .dump para comprobar que el archivo no sufrió truncamiento o corrupción antes de lanzar el restore.
